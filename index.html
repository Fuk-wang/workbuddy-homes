IMA Knowledge Base

核心功能：对接 IMA 知识库

把 ima 里的私有文档和截图挂进对话，让回答基于你自己的素材，而不是泛泛的互联网印象。

01开始之前，先确认三件事

  • 桌面端已登录 WorkBuddy：客户端能正常启动、发起一轮对话（个人账号、企业账号都可以）。
  • ima 里有可用的知识库：个人版连接器用个人微信扫码授权；企业账号会同时看到「企业版」和「个人版」两个连接器，企业版走企业统一身份。
  • 库里有内容：知识库里已经放进了文档或截图——空库接进来，没有东西可引用。

检查怎么确认已经就绪

  • 「资料库 → ima 知识库」里能看到连接器，状态显示为「已连接」。
  • 知识库列表能读到库名，新建任务时在输入框上方的上传图标里能勾选到它。
授权后 WorkBuddy 获得三项权限：查看你的知识库列表、查看或搜索库内资料、把文件加进任务或存回 ima。两项检查都成立再往下走。

02四步把知识库接进来

  1. 1打开资料库左侧边栏点「资料库」，选择「ima 知识库」。
  2. 2扫码授权点「立即前往授权」，用微信扫码登录 ima 并确认授权，连接状态会立即刷新。
  3. 3把资料加进任务新建任务时，在输入框上方的上传图标处打开 ima 知识库，勾选整个库或选文件后确定；也可以在资料库里选中文件「添加到任务」。
  4. 4产物存回 ima右侧「产物」里选中文件 →「上传到云端」→ 选 ima 知识库（个人 / 共享 / 订阅）。

提示这一步最容易出问题的地方

  • 先授权、再加库、最后提问：顺序反了，这一轮回答不会带上知识库内容。
  • 企业版连接器不能在端内解绑（由企业统一管理）；个人版随时可以在 ima 知识库右上角 ⋯ →「解除绑定」。
  • 提问时写明范围（比如「只根据这个库回答」），能明显减少跑题。

03接通之后能得到什么

让回答落在你自己的文档、截图素材上——依据来自你放进知识库的东西，而不是模型的公开印象。

私有文档里的具体条款 截图里的表格与数据 内部术语、代号、项目名 同一份材料的多轮追问

对比接与不接的区别

  • 不接知识库：只能回答公开常识，问到你自己的材料就开始含糊。
  • 接上知识库：答案落在你的素材里，还能顺着同一份材料继续追问。
知识库仍归 ima 管理：WorkBuddy 只在授权范围内读取、写入，不会把文件复制到别的地方。
Get Started

两种用法，按你的习惯挑一个

普通用户走图形版，鼠标点几下就能用；开发者走命令行版，方便接进脚本和现有的工作流。

桌面端（图形界面）

面向普通用户

官网下载安装包，微信扫码登录就能开工。Windows 64 位和 macOS（Apple 芯片 / Intel）都有安装包；Linux 目前没有官方版本。

  1. 1下载安装包官网 → 下载 → 选当前系统的版本；历史版本页也按版本列出 macOS（Apple 芯片 / Intel）与 Windows 64 位安装包。
  2. 2运行安装包双击后按引导选择安装用户（建议「仅为我安装」）和安装位置，完成后启动。
  3. 3微信扫码登录个人用户选个人登录，买了企业版的选企业登录，在浏览器里扫码完成验证。
  4. 4新建任务描述需求，可指定工作空间目录；用 @ 引用文件，Ctrl/Cmd + V 直接粘贴截图。
  5. 5查看产物结果在右侧窗口，「产物」里是交付文件，其他文件在「概览 - 工作空间文件」。
全程不用碰配置文件：模型在输入栏的下拉里换，资料在「资料库」里接。

命令行（CodeBuddy Code）

面向开发者

先说清楚：WorkBuddy 桌面工作台没有官方命令行接口。腾讯的命令行工具是另一款产品 —— CodeBuddy Code（腾讯云代码助手），命令是 codebuddy / cbc，适合写进脚本和 CI。

bash · 常用命令 
# 安装（需要 Node.js 18.20.8+）
npm install -g @tencent-ai/codebuddy-code

# 启动交互式会话（也可以输入短名 cbc）
codebuddy

# 单次提问，打印结果后退出
codebuddy -p "总结这个仓库的目录结构"

# 管道：把日志直接喂进去
cat logs.txt | codebuddy -p "分析这些日志里的错误"

# 继续最近一次对话
codebuddy -c
以上命令来自 codebuddy.cn/docs/cli 官方 CLI 参考（2026-10 版），复制到本机终端才有效；本页不会执行它们。
CLI Reference

CodeBuddy Code 命令与参数

下面每一条都出自腾讯云 CodeBuddy 的官方 CLI 参考（2026-10 核对），不是编的示例。点标题展开参数表和调用示例。

先把两个产品分开：WorkBuddy 是桌面智能体工作台，图形界面，没有官方 CLI；CodeBuddy Code 是终端里的编程 Agent，命令是 codebuddy / cbc。两者账号与文档各自独立，别把它们当成同一个程序的两种用法。

在项目目录里开一个持续的对话窗口，直到手动退出。短名 cbc 和 codebuddy 是同一个命令。

参数说明
<初始提示词>可选。带一句话直接开始，例如 codebuddy "解释这个项目"。
--model <name>指定本次会话的模型，要填模型 ID，如 glm-5.2、hy3、deepseek-v4.1-flash、kimi-k2.6。官方帮助写明「请提供模型 ID」，没有 sonnet / opus 这类别名；ID 随版本与账号不同，以 /model 面板或报错里列出的为准。
--add-dir <path>额外允许访问的工作目录，可传多个路径。
-c, --continue加载当前目录最近一次对话，接着上次继续。
# 进入项目目录后直接启动 codebuddy # 带一句初始提示词，并指定模型 codebuddy "解释这个项目的目录结构" --model glm-5.2 # 接着最近一次对话继续 codebuddy -c
来源：codebuddy.cn/docs/cli/cli-reference · codebuddy.cn/docs/cli/README

打印回答后退出，不进交互界面。脚本、CI、定时任务都走这条路；非交互模式下涉及读写文件或执行命令时，必须给一个明确的权限策略。

参数说明
-p, --print打印响应后退出，不进入交互模式。
--output-format可选 text / json / stream-json；给程序解析时用 json。
--max-turns <n>限制非交互模式下代理的轮次数，防止跑飞。
-y, --dangerously-skip-permissions跳过大部分权限提示。它不是真正的全放行，HIGH / CRITICAL 级命令仍可能要求确认，谨慎使用。
# 单次提问，直接输出 codebuddy -p "总结 src 里每个模块的职责" # JSON 输出，交给别的程序解析 codebuddy -p "检查类型错误" --output-format json # 需要读文件时，非交互模式要显式给权限 codebuddy -p "为 utils.js 补单元测试" -y
来源：codebuddy.cn/docs/cli/cli-reference · codebuddy.cn/docs/cli/quickstart

像 grep 一样吃标准输入：日志、diff、提交历史都能直接喂进去，让它只输出结论。官方 README 把这一条列为 Unix 哲学的集成方式。

写法说明
cmd | codebuddy -p "…"管道内容会成为提示词的上下文，配合 -p 使用。
cat file | codebuddy不带 -p 也能读，但会进入交互界面，脚本里一般不需要。
# 让它在提交历史里找问题 git log --oneline -30 | codebuddy -p "分析这些提交，找出可能的问题" # 错误日志归类 cat error.log | codebuddy -p "把这些错误归类，指出最可能的根因"
来源：codebuddy.cn/docs/cli/README（Unix 集成示例）

关掉终端之后，上下文还在：可以接着当前目录最近的一次会话，也可以按 session id 精确恢复某一次。

参数说明
-c, --continue加载当前目录最近的一次对话。
-r, --resume <id>按 session id 恢复指定会话，可同时带一句新提示。
# 接着最近一次对话继续干活 codebuddy --continue -y # 按 ID 精确恢复 codebuddy --resume abc123 "把上次那个冲突解决掉"
来源：codebuddy.cn/docs/cli/cli-reference

这些是在 codebuddy 会话里敲的斜杠命令，不是终端命令——别在 shell 里直接输入。

命令说明
/init初始化项目上下文。官方建议开局先跑一次，后续回答更贴项目结构。
/model在当前会话里切换模型。
/config打开设置，包括界面语言（想固定用中文回复就改这里）。
# 进入 codebuddy 交互界面后输入 /init /model /config
来源：codebuddy.cn/docs/cli/quickstart · 腾讯云文档「CodeBuddy CLI 登录与模型配置」

Node.js 18.20 以上用 npm 全局安装；升级优先用内置的 update，它失败再用包管理器重装。

命令说明
--version验证安装：输出版本号即装好了。
update自动检测安装方式并更新到最新版。
cbccodebuddy 的等价短命令。
# 全局安装（npm / pnpm / yarn / bun 都行） npm install -g @tencent-ai/codebuddy-code # 验证 + 升级 codebuddy --version codebuddy update
